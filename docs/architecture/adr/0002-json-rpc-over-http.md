# ADR-0002: JSON-RPC 2.0 over HTTP

- 상태: 승인
- 날짜: 2026-08-19

## 배경

현행 서버는 여러 REST Controller와 경로를 사용합니다. 사용자 요구사항은 JSON-RPC 2.0 스펙을 따르는 것입니다. JSON-RPC는 전송 방식을 정의하지 않으므로 HTTP 결합 규칙을 별도로 결정해야 합니다.

## 결정

- 모든 게임 RPC는 `POST /rpc`로 제공합니다.
- 단일, 알림, 배치 Request를 지원합니다.
- 유효한 JSON-RPC 처리 결과는 업무 오류를 포함해 HTTP 200을 사용합니다.
- 응답할 항목이 없는 알림 또는 전체 알림 배치는 HTTP 204를 사용합니다.
- Content-Type, 요청 크기, HTTP 메서드, 디스패치 전 속도 제한은 전송 계층 상태 코드로 처리합니다.
- 운영 상태 확인은 `GET /health`로 분리합니다.

## 결과

- 클라이언트 진입점과 서버 디스패치가 단순해집니다.
- HTTP 상태만으로 업무 성공 여부를 판단할 수 없으므로 클라이언트가 JSON-RPC error를 처리해야 합니다.
- 배치의 모든 요소가 같은 Bearer 인증 문맥을 공유합니다.
- OpenAPI Controller 자동 생성 대신 JSON 예제와 계약 테스트가 중요해집니다.

## 대안

- REST 유지: 사용자 요구사항과 불일치하여 채택하지 않음
- WebSocket JSON-RPC: 현재 비동기 요청/응답 범위에 불필요한 연결 상태가 추가되어 채택하지 않음
