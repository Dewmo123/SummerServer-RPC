# 한국어 주석 가이드

## 목적

AI를 사용해 변경된 코드의 주석을 한국어로 정비하되, 코드를 그대로 번역한 설명이나 추측성 설명을 만들지 않기 위한 기준입니다.

## 주석을 작성할 때

- JSON-RPC 스펙상 놓치기 쉬운 불변 조건
- 동시성 선점과 트랜잭션 순서의 이유
- 보안상 원문을 저장하거나 로그로 남기지 않는 이유
- 단순화된 게임 규칙과 향후 변경 시 주의점
- 외부 시스템 또는 SQLite 제약 때문에 선택한 우회 방식
- 공개 API의 입력, 출력, 예외 계약

## 주석을 작성하지 않을 때

- 코드 한 줄을 한국어 문장으로 다시 설명할 때
- 타입과 메서드 이름만으로 의미가 분명할 때
- 작성자가 확인하지 못한 의도를 추측할 때
- 변경 이력이나 담당자를 코드에 기록할 때
- AI 생성 여부를 표시할 때
- 오래된 TODO를 issue나 요구사항 ID 없이 남길 때

## XML 문서 주석

공개 인터페이스, 공용 값 객체, 규격 처리 타입에는 소비자가 알아야 할 계약이 있을 때 XML 문서 주석을 사용합니다.

```csharp
/// <summary>
/// JSON-RPC 요청 ID의 원래 JSON 타입과 값을 보존합니다.
/// </summary>
/// <remarks>
/// 속성 자체가 생략된 알림과 명시적인 null ID를 구분해야 합니다.
/// </remarks>
public readonly record struct JsonRpcIdProto(...);
```

내부 구현 세부를 공개 XML 주석에 노출하지 않습니다.

## TODO 형식

미확정 작업은 요구사항이나 issue를 연결합니다.

```csharp
// TODO(FR-RAID-001): 약탈 결과 검증 계약이 확정되면 서버 권위 검증을 추가한다.
```

기한이나 소유자 없는 `TODO: 나중에`는 금지합니다.

## AI 주석 재작성 프롬프트

```text
현재 스테이징된 C# diff에서 추가되거나 변경된 주석만 검토하라.

규칙:
- 주석은 자연스러운 한국어로 작성한다.
- 코드가 무엇을 하는지 그대로 번역한 주석은 제거한다.
- 업무 규칙, JSON-RPC 불변 조건, 동시성, 트랜잭션, 보안 이유만 남긴다.
- 확인할 수 없는 의도는 추측하지 말고 주석을 만들지 않는다.
- 기존 동작이나 공개 계약을 변경하지 않는다.
- XML 문서 주석은 소비자가 알아야 하는 계약만 설명한다.
- AI가 작성했다는 표시를 남기지 않는다.

수정 후 어떤 주석을 제거·재작성했고 그 이유가 무엇인지 요약하라.
```

## 리뷰 체크리스트

- 주석이 코드와 현재 계약에 일치하는가?
- `왜` 또는 `주의할 불변 조건`을 설명하는가?
- 주석을 제거해도 코드 이름만으로 충분한가?
- 보안 정보나 운영 내부 경로를 드러내지 않는가?
- 관련 요구사항 ID나 규격 근거가 정확한가?
- 맞춤법과 용어가 `DOMAIN_GLOSSARY.md`와 일치하는가?
