# 주요 유스케이스

## UC-01 Google 최초 로그인

주체: 인증되지 않은 플레이어, Google 인증 서비스

정상 흐름:

1. 클라이언트가 Google ID 토큰으로 `auth.login.google`을 호출합니다.
2. 서버가 허용된 Client ID와 토큰의 유효성을 검증합니다.
3. 서버가 제공자와 제공자 사용자 ID 조합을 조회합니다.
4. 사용자가 없으면 외부 식별자를 직접 노출하지 않는 초기 사용자명으로 계정을 생성합니다.
5. 서버가 JWT 액세스 토큰과 리프레시 토큰 패밀리의 첫 토큰을 생성합니다.
6. 서버가 사용자 정보와 두 토큰의 만료 시각을 반환합니다.

대안 흐름:

- 같은 계정의 최초 로그인이 동시에 들어오면 DB 유일 제약으로 하나만 생성하고 나머지는 생성된 사용자를 다시 조회합니다.
- Google 토큰이 유효하지 않으면 사용자 또는 세션을 만들지 않습니다.

관련 요구사항: FR-AUTH-001, FR-AUTH-003, FR-AUTH-004

## UC-02 세션 갱신과 재사용 탐지

주체: 인증되지 않은 플레이어

정상 흐름:

1. 클라이언트가 현재 리프레시 토큰으로 `auth.token.refresh`를 호출합니다.
2. 서버가 토큰 해시, 만료, 사용, 폐기 상태를 확인합니다.
3. 서버가 같은 패밀리와 절대 만료를 가진 새 리프레시 토큰을 생성합니다.
4. 조건부 갱신으로 기존 토큰을 한 번만 사용 처리합니다.
5. 서버가 새 액세스 토큰과 리프레시 토큰을 반환합니다.

재사용 흐름:

1. 이미 사용된 토큰이 다시 제출됩니다.
2. 서버가 해당 패밀리의 미폐기 토큰을 모두 폐기합니다.
3. 서버가 재사용 탐지 오류를 반환합니다.

관련 요구사항: FR-AUTH-004

## UC-03 캐릭터와 재화 초기화 조회

주체: 인증된 플레이어

정상 흐름:

1. 플레이어가 `character.getMine` 또는 `currency.listMine`을 호출합니다.
2. 서버가 JWT의 사용자 ID를 확인합니다.
3. 누락된 캐릭터 또는 재화 행을 유일 제약과 충돌 무시 삽입으로 생성합니다.
4. 서버가 완전한 현재 상태를 반환합니다.

예외 흐름:

- 토큰의 사용자 ID에 해당하는 사용자가 없으면 새 게임 데이터를 만들지 않고 인증 오류를 반환합니다.

관련 요구사항: FR-CHAR-001, FR-CURRENCY-001, FR-CURRENCY-002

## UC-04 스테이지 입장

주체: 인증된 플레이어

정상 흐름:

1. 플레이어가 스테이지 ID로 `stage.enter`를 호출합니다.
2. 서버가 정적 카탈로그에서 스테이지를 찾습니다.
3. 서버가 사용자의 기존 진행 중 실행을 모두 포기 처리합니다.
4. 서버가 서버 UTC 시작 시각을 가진 새 실행을 생성합니다.
5. 서버가 실행 ID와 스테이지 데이터를 반환합니다.

트랜잭션 경계: 3번과 4번은 함께 커밋되거나 함께 롤백됩니다.

관련 요구사항: FR-STAGE-002

## UC-05 스테이지 완료와 보상

주체: 인증된 플레이어

정상 흐름:

1. 플레이어가 실행 ID로 `stage.complete`를 호출합니다.
2. 서버가 실행 존재 여부, 소유권, 진행 상태, 최소 클리어 시간을 검사합니다.
3. 조건부 갱신으로 완료 권한을 선점합니다.
4. 서버가 실행에 획득 Gold와 경험치를 기록합니다.
5. Gold 잔액을 원자적으로 증가시킵니다.
6. 경험치를 증가시키고 필요한 만큼 레벨을 올립니다.
7. 서버가 획득량과 갱신된 전체 상태를 반환합니다.

대안 흐름:

- 두 완료 요청이 동시에 들어오면 하나만 3번에 성공합니다.
- 보상 처리 중 하나라도 실패하면 실행 완료와 모든 보상을 롤백합니다.
- 최소 시간이 지나지 않았으면 실행 상태를 바꾸지 않습니다.

관련 요구사항: FR-STAGE-003, FR-CHAR-002, FR-CURRENCY-003

## UC-06 내 방 저장

주체: 인증된 플레이어

정상 흐름:

1. 플레이어가 맵 ID와 함정 배열로 `room.upsertMine`을 호출합니다.
2. 서버가 맵 존재 여부와 요청 크기를 확인합니다.
3. 서버가 함정 종류, 경계, 중복 좌표, 회전값을 검증합니다.
4. 서버가 사용자별 최신 방을 생성하거나 전체 교체합니다.
5. 서버가 정규화된 방 데이터를 반환합니다.

예외 흐름:

- 검증이 하나라도 실패하면 기존 방은 변경하지 않습니다.
- 존재하지 않는 사용자는 방을 만들 수 없습니다.

관련 요구사항: FR-ROOM-001

## UC-07 JSON-RPC 배치 처리

주체: 게임 클라이언트

정상 흐름:

1. 클라이언트가 하나 이상의 요청을 Array로 전송합니다.
2. 서버가 각 요소를 독립적인 JSON-RPC 요청으로 검증하고 순차 처리합니다.
3. 알림 요소의 결과는 응답에서 제외합니다.
4. 일반 요청의 응답을 Array로 반환합니다.

대안 흐름:

- 빈 Array는 단일 `Invalid Request` 오류 객체를 반환합니다.
- 잘못된 요소는 해당 위치에 대응하는 `Invalid Request` 오류를 생성합니다.
- 모든 요소가 알림이면 응답 본문을 만들지 않습니다.

관련 요구사항: NFR-PROTOCOL-001

## UC-08 로그아웃

주체: 플레이어

정상 흐름:

1. 클라이언트가 리프레시 토큰으로 `auth.logout`을 호출합니다.
2. 서버가 토큰을 찾으면 패밀리의 활성 토큰을 모두 폐기합니다.
3. 서버가 성공 결과를 반환합니다.

보안 흐름:

- 토큰이 없거나 이미 폐기되어도 동일한 성공 결과를 반환해 토큰 존재 여부를 노출하지 않습니다.

관련 요구사항: FR-AUTH-005
